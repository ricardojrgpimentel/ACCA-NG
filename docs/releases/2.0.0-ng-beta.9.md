# AccA-NG 2.0.0-ng-beta.9

Version code **49**. The installed ACC module version now appears directly below
the app version in **About**, without expanding Technical information. It
refreshes when the screen opens/resumes and reads the actual installed engine,
with bounded unavailable/legacy handling. NG API information is read from
metadata without initializing the daemon.

The bundled engine remains [ACC-NG v1.0.9-ng/202610129](https://github.com/ricardojrgpimentel/ACC-NG/releases/tag/v1.0.9-ng).
There is no module update in this release. Existing localized labels are reused.

## Install and validation

Install **AccA-NG-2.0.0-ng-beta.9.apk** over the previous official AccA-NG app.
Package `com.accang.app` and the established signing certificate are retained;
keep app data to preserve profiles and preferences. Only the APK is needed.
`SHA256SUMS`, the public certificate and `signature-verification.txt` support
independent verification.

**119 release tests**, release lint/build, APK signature and 16 KiB alignment
passed. The signed Samsung SM-G975F update showed `v1.0.9-ng (202610129)` in the
initial About viewport and NG API `1` in technical details. Database rows,
preferences, config/last-good and a single ready daemon were preserved against
the immediate pre-update snapshot. The embedded module is byte-identical to
the published v1.0.9-ng tarball.

This is a **prerelease**. The engine's existing physical scope remains
Samsung/Magisk; successful writable mcc/mcv, independent OEM policy, other
OEM and KSU/APatch certification remain pending. See the
[validation record](https://github.com/ricardojrgpimentel/ACCA-NG/blob/v2.0.0-ng-beta.9/docs/acc-ng-validation.md).
